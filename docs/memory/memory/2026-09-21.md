## Generic staging infrastructure representation fix

The first repository-staging spec failed before modification because its D-025
semantic marker did not match the exact reviewed title. The corrected spec then
reached the final staging identity gate and failed because the generic helper
compared raw worktree SHA-256 with staged Git bytes for `run_package.cmd`.

The isolated staging clone had legitimately normalized the CMD text
representation through Git's clean-filter boundary. No commit or push occurred;
the control root and commissioned runtime remained unchanged.

The permanent staging engine now treats raw worktree bytes and staged Git blobs
as separate authorities. It verifies raw source SHA-256 first, then derives the
expected filtered Git blob OID with the staging checkout and compares that OID to
the index. Regression coverage includes a CRLF worktree / LF index case.
