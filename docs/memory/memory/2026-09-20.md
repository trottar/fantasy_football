Classification:

tracked text is compared against `HEAD:<path>` after normalizing only CRLF/CR to

post-apply allowlist.

## Memory reconciliation v5 failure and authority correction

v5 failed safely before modification and again listed essentially the entire
memory tree as drift. No project/runtime file was modified; staging/commit/push
were not attempted.

The repeated v3-v5 failure pattern established that the problem was not newline
or Git-clean-filter representation. The wrong **authority surface** was being
used. The synchronized control root's local Git metadata can lag files copied
back from a successfully pushed isolated staging clone.

Final correction: local apply now validates only package targets against the
known predecessor remote checkpoint blob identities embedded in the package.
The control root's local `HEAD` is informational only during this phase. A fresh
isolated staging clone owns Git `HEAD`/index/manifest/commit/push authority after
the successful local apply is returned and verified.

`../evidence/MEMORY_HANDOFF_RECONCILIATION_ROOT_CAUSE_2026-09-20.md`.

## Memory reconciliation push v1 failed before staging/commit/push

After the successful v6 local memory apply, the first separate push script
verified all 22 local payload files and observed remote `main` at
`f22115e7c75357e4321912831a3f99d1ea3e5c3f`. The isolated `git clone` began
successfully, but the first post-clone Git-wrapper call failed as bare
`git -C <staging-path>` with no subcommand.

Classification:
`FAILED BEFORE STAGING / FAILED BEFORE COMMIT / FAILED BEFORE PUSH`.

The project control root, football/model source, runtime tree, Git index, and
remote branch were not modified by this failure. A temporary isolated clone may
have been created and is disposable.

Exact root cause: the push script declared `Invoke-Git` as
`param([string]$Repo, [string[]]$Args)`. PowerShell parameter names are
case-insensitive and `$args` is an automatic variable, so this formal parameter
name collided with the automatic variable. The intended `rev-parse HEAD`
arguments were therefore lost and the wrapper executed only `git -C <repo>`.
Every later `Invoke-Git` call in that script was affected by the same defect.

Successor requirement: use an unambiguous formal parameter such as `$GitArgs`
or `$CommandArgs`, update every named call site, statically reject a formal
parameter named `$Args`, and execute a concrete wrapper self-test before clone
or staging.

Canonical evidence:
`../evidence/MEMORY_HANDOFF_PUSH_V1_FAILURE_2026-09-20.md`.
