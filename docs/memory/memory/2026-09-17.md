## Memory checkpoint push v1 — failed before commit/push

The first `fantasy_memory_checkpoint_push_v1` Windows run reached the isolated
GitHub clone step and stopped with PowerShell `NativeCommandError` on Git's normal
`Cloning into '...'` progress message.

Classification: `FAILED BEFORE COMMIT/PUSH`.

Measured facts:
- the local project Git root resolved successfully;
- no football/model source was modified by the push tool;
- no staging commit had been created;
- no `git push` had executed;
- a read-only GitHub check afterward confirmed `main` remained at
  `a97e0066d89f921c65811aca5b983d216d481b2e`.

Root cause:
Windows PowerShell 5.1 can promote native-process stderr records into terminating
`NativeCommandError` under `$ErrorActionPreference = 'Stop'`, even when the
native program is only writing normal progress output.

v2 correction:
the Git wrapper temporarily uses non-terminating PowerShell error handling while
Git executes, captures combined output, restores the prior preference, and judges
success/failure from `$LASTEXITCODE`.

This is a tooling/procedure correction only. Football physics/model code is
unchanged.

## Manifest repair v1 — PowerShell parser failure before modification

The first `fantasy_memory_manifest_repair_v1` local run did not execute because
Windows PowerShell rejected two interpolated exception strings at parse time:

- `Byte-count mismatch for $rel: ...`
- `SHA-256 mismatch for $rel: ...`

Classification: `FAILED BEFORE MODIFICATION`.

Because parsing failed before script execution:
- no local durable-memory file was modified by v1;
- no backup/write phase started;
- no staging clone was created;
- no commit was created;
- no push ran;
- a subsequent read-only GitHub check confirmed `main` remained at
  `28485d27bd436f6f158da2a4d34671497238559a`.

Root cause:
in a double-quoted PowerShell string, an unbraced variable immediately followed
by `:` can be parsed as a scoped/drive-style variable reference. `$rel:` is
therefore not a safe interpolation form.

v2 correction:
the affected messages use the `-f` format operator rather than adjacent
`$variable:` interpolation. Package validation also scans the script for this
parser-risk pattern before delivery.

This is a tooling-only correction. Football/model/application source remains
unchanged.
