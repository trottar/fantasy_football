## Procedure audit adopted

Audited the durable-memory/problem-solving structure in `trottar/onn-stream-test` for procedure only. No domain-specific PrivyHub/streaming design was imported.

Adopted process-level patterns:
- explicit authority/freshness ordering;
- typed memory instead of one monolithic append-only file;
- one narrow question/hypothesis per diagnostic cycle;
- decision boundaries defined before measurement;
- diagnostic-only probes while cause/architecture remains uncertain;
- raw measurements outrank classifiers;
- preserve measured history while superseding incomplete interpretations;
- explicit decision/investigation status;
- exact local receipts/hashes can outrank reconstructed historical Git expectations;
- source/package/runtime/commissioning validation are distinct;
- explicit `FAILED BEFORE MODIFICATION` / `ROLLED BACK` / `INSTALLED SUCCESSFULLY` states;
- stable-subsystem boundaries and no unrelated cleanup;
- patch ZIP + memory update as one communication checkpoint;
- detailed timestamped progress/debug output for long procedures.

The previous local memory-patch failure also established a project-specific procedural lesson: do not assume `docs/memory` exists at the requested project root merely because the GitHub repository contains it. Resolve the actual Git worktree and inspect local paths first.
