# D-026 — Active Memory Semantic Integrity

**Status:** ACTIVE

## Decision

Promote deterministic active-memory semantic integrity from a manual review habit
to an executable strict-health contract where repository state can establish the
fact without interpreting football outcomes.

Structural validity alone is insufficient. A memory tree must not report healthy
while its active documents contradict their own durable repository state.

## Enforced Deterministic Contracts

The strict checker may enforce facts derivable from repository text/path state,
including:

- `CURRENT.md` must not use its exact next action to instruct publication of the
  checkpoint whose active content is already being read;
- a stable `CURRENT_HANDOFF.md` that says no exceptional transfer state exists
  must contain no additional transfer residue;
- weeks earlier than `CURRENT.md`'s `nfl_week` may not remain labeled active,
  upcoming, or as a current hard-capture gate in `roadmap/SEASON_2026.md`;
- `DECISION_LOG.md` must index every canonical `D-NNN_*.md` decision record;
- the weekly decision receipt template must exist and the weekly recap must
  include decision-completion / operational-health linkage;
- current memory-update and diagnostic QA procedures must use the commissioned
  `.ffpkg` delivery contract rather than ZIP-era instructions;
- active status/known-issue surfaces may be checked for narrow deterministic
  stale-state markers selected by regression evidence.

Every new checker branch requires a positive and controlled negative regression.
The checker remains observational and never rewrites repository files.

## Non-Authority Boundary

The checker does **not** infer:

- whether a football recommendation is correct;
- whether an empirical calibration gate has passed;
- whether a weekly action family was actually executed;
- whether a runtime/provider health receipt is current unless represented by an
  explicit machine-checkable repository contract;
- whether a production repair is authorized.

Strict memory health remains one operational-health receipt, not the weekly
completion authority itself.

## Mutation / Delivery Rule

Deterministic mutation packages must derive predecessor identities and any text
markers from exact authoritative source representations. Marker cardinality must
be proven before delivery. When whole-file replacement under exact predecessor
identity is simpler and safer than chained string replacement, prefer the
whole-file result.

The operator must not be the first executor of deterministic package validation.
Exact extracted-carrier behavior must be exercised in a disposable predecessor
environment before delivery when the environment permits.

## Scientific Boundary

This decision changes repository memory/tooling only. It does not authorize
football/model/application source repair, alter `P ⊕ D ⊕ K`, tune v0.X, backfill
prospective evidence, activate persistence, or authorize transactions.
